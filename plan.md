## 1. EXECUTION RULES (follow in EVERY run, no exceptions)

### 1.1 Process rules
1. **Read first.** At the start of every session, read `PLAN.md` fully and check Section 12 for the current state. Never restart finished work.
2. **One task at a time.** Execute only the task(s) requested. Do not jump ahead to later phases.
3. **Plan before coding.** For each task, state in 3-5 lines what files you will create or change, then implement.
4. **Do not invent requirements.** If something is ambiguous, use the decision in Section 3. If it is not covered there, pick the simplest option, and append it to Section 13 (Decision Log).
5. **Stay in scope.** No extra features, no new dependencies, no refactors of unrelated code unless the task says so. Bonus items are only done in their own phase.
6. **Never edit generated code.** `finance_sdk/` is generated by OpenAPI Generator CLI. Regenerate, never hand-edit.
7. **Never use Docker** (forbidden by the challenge).
8. **Never hardcode secrets or absolute paths.** Use `config.py` and env variables with defaults.

### 1.2 Code quality rules
9. **Layering is mandatory:** `routers/` (HTTP only) -> `services/` (business logic) -> `models.py` (DB). No business logic in route functions. No SQL in routers.
10. **Dependency injection:** every DB access goes through `db: Session = Depends(get_db)`. Never create a session inside a route or service.
11. **Type hints everywhere** (Python) and **docstrings** on every public function/service method.
12. **Pydantic schemas for all request and response bodies.** Every route declares `response_model`, `status_code`, `tags=["transactions"]`, and a unique `operation_id` (needed for clean SDK method names).
13. **Small functions, clear names, no duplicated code.** Constants (keyword maps, window length) live in one place.
14. **Consistent error format.** All errors return JSON: `{"detail": "<human readable message>"}`. Never leak stack traces.
15. **Use the exact HTTP codes in Section 5.** Do not improvise.

### 1.3 Data-correctness rules (the "trick logic": never break these)
16. **Sign convention:** expenses are **stored negative**, income **stored positive**. The API **always returns absolute values** (`amount`, summary totals).
17. **Client input amount is always positive** (`> 0`). Server applies the sign.
18. **Type is only `income` or `expense`** (Pydantic `Literal` + DB CHECK constraint).
19. **Auto-categorization is case-insensitive** and runs on create. Fallback category is `Uncategorized`.
20. **Manual reclassify sets `auto_tagged = 0`** and must never be overwritten by auto-tagging.
21. **Duplicate = same normalized description + same stored amount + same type within the window** (Section 3). Returns `409`.
22. **Summary groups by month (`YYYY-MM`) and category**, using the transaction `timestamp`.

### 1.4 Verification rules (before declaring a task done)
23. **Run it.** After writing code, run the relevant command (`pytest`, `alembic upgrade head`, `npm run build`, etc.) and confirm it passes. Do not claim success without running.
24. **Write tests with the feature**, not afterwards. Every backend rule in 1.3 must have at least one test.
25. **Never break earlier work.** Run the full test suite (`pytest -v`) after every backend change.
26. **Check Swagger** (`/docs`) still loads after any route/schema change.
27. **Report format at end of every task:** (a) files created/changed, (b) commands run and results, (c) anything skipped or assumed, (d) next suggested task.

### 1.5 Platform rules
28. Target **Windows** for scripts (`.bat`), but keep Python and Node code cross-platform.
29. Use **forward-compatible versions:** Python 3.10+, Node 18+.
30. Pin dependencies in `requirements.txt` after installing (`pip freeze` for the packages used).

## 5. API CONTRACT (exact behavior)

| Method | Path | operation_id | Success | Errors |
|---|---|---|---|---|
| POST | `/transactions/` | `create_transaction` | 201 + TransactionOut | 409 duplicate, 422 invalid/semantic |
| GET | `/transactions/` | `list_transactions` | 200 + list | 422 bad filter |
| GET | `/transactions/summary` | `get_summary` | 200 + list | 422 bad month |
| DELETE | `/transactions/{transaction_id}` | `delete_transaction` | 204 | 404 |
| PATCH | `/transactions/{transaction_id}/reclassify` | `reclassify_transaction` | 200 + TransactionOut | 404, 422 |

**Rules:**
- `/summary` must be declared **before** `/{transaction_id}` routes.
- `GET /transactions/` filters: `month` (`YYYY-MM`), `type` (`income|expense`), `category` (case-insensitive exact match).
- Request `POST`: `{description: str (1-200, stripped), amount: float > 0, transaction_type: "income"|"expense"}`.
- Response `TransactionOut`: `{id, description, amount (absolute), transaction_type, category, auto_tagged, timestamp}`.
- Request `PATCH`: `{category: str (1-50, stripped)}`.
- Unhandled exceptions -> `500` with `{"detail": "Internal server error"}`.
